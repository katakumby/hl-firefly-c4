# Implementation and conformance

Inspect the working project's standards, chain, language, and existing toolchain before asking for missing context. Follow that repository's instructions for edits and tests.

Read the chosen specification, relevant required standards, compatibility notes, and security considerations. Read additional sections when they carry requirements. A dependency or example implementation does not make every optional feature mandatory.

Connect requirements to code behavior and observable tests. Record source evidence, obligation strength, implementation behavior, and the relevant check. Consider signatures/encoding, returns/errors, events, authorization, state transitions, callbacks, boundaries, rounding, replay domains, and optional extensions only where specified.

Use the project's established framework. Archived inline examples can be old or incomplete; do not copy them blindly. Retrieve an upstream asset only when needed, inspect it before execution, and keep generated implementation files in the user's project rather than this skill.

Report the revisions and extensions assessed, requirement citations, changes or findings, and tests performed. Mark untested requirements honestly. Distinguish conformance defects, broader security concerns, and optional improvements. Neither compilation nor conformance proves a comprehensive security audit or chain activation.
